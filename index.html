Pre-computed result portal

Enter a roll number from 2710000000 to 2710004999, or pick one at random. If the site is busy, this page waits and retries for you.

How this works

This page uses design C2 from the study: every result is computed before release and stored as one small file per student. Looking up a result is just fetching that file, here from GitHub Pages and its content delivery network. There is no database and no server-side code on the read path.

  • In our experiments this design served every student at ten times the load that broke a database-backed portal, using far less CPU.
  • The page backs off and retries on errors instead of making students press refresh, because refreshes multiply the load on a busy server.

Code, experiments and paper: github.com/K144U/NoCrashing.
