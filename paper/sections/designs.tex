\section{Designs Under Test}
\label{sec:designs}

Every design serves \texttt{GET /result?roll=$n$} with the same JSON body, uses
the same synthetic data, and gets the same budget of two CPUs for the read
path (Table~\ref{tab:designs}). Fig.~\ref{fig:designs} shows how each design
answers a request. Before the announced release time every design answers
``not released'' without touching result data.

\textbf{Server model.} All designs that run application code use the same Go
server. It works on at most 256 requests at once and lets at most 4096 more
wait; beyond that it answers 503. Real web servers are limited in the same
way: Apache, for example, serves at most \texttt{MaxRequestWorkers} requests at
once (256 by default in its prefork mode) and queues further connections up to
a fixed backlog~\cite{apache2026mpm}. In early tests without such a limit,
design~A took on work until it was killed for exceeding its memory limit.

Our server is a small Go program, while real portals run full web frameworks
with sessions and templates. To stand in for that work, every page built from
the database costs \SI{5}{ms} of CPU. Pre-computed designs store finished
pages and never pay this cost; cache-aside pays it on every miss. The value
\SI{5}{ms} is an assumption (Section~\ref{sec:threats}).

\textbf{Waiting room.} Our waiting room admits students at a fixed rate (80\%
of the backend's calibrated capacity) and tells the others their position.
Two queue policies are compared: first-come-first-served (FIFO), and a
lottery that shuffles everyone who arrived before release, as some products
offer~\cite{cloudflare2026queue}. Two ticket implementations are compared: a
\emph{naive} ticket held only in the page (lost when the student presses
refresh) and a \emph{token} kept in a signed cookie (kept on refresh).
Tickets whose holder has not polled for 30\,s are skipped. An admitted student
may use the backend for 60\,s; the waiting room limits neither how many
admitted students are active at once nor how many requests each one sends.
